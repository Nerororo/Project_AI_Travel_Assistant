# Definition of Done

## 1. 목적

이 문서는 구현됨, 검증됨, 운영 가능함을 구분한다. 현재 상태는 `docs/07-implementation-readiness.md`에서 관리하고 이 문서에는 완료 판정 기준만 둔다.

체크리스트는 해당 기능에 적용되는 공통 항목과 도메인 항목을 모두 충족해야 한다. Accepted ADR이나 작성된 설계, 컴파일 성공만으로 기능을 완료 처리하지 않는다.

## 2. 완료 상태의 의미

| 상태 | 의미 |
|---|---|
| 설계됨 | 요구사항과 계약이 문서화됨 |
| 구현됨 | 코드가 존재하고 컴파일됨 |
| 검증됨 | 필수 자동 테스트와 전체 테스트를 통과함 |
| 운영 가능 | 비밀값·관측·쿼터·제공자 정책·배포 조건까지 충족함 |
| 차단됨 | 외부 답변이나 선행 결정 없이는 완료 판정 불가 |

카카오 좌표의 작성 중 일시 활용과 즉시 폐기 구조는 2026-09-11 DevTalk 답변으로 허용 범위를 확인했다. 정책 확인만으로 관련 기능을 완료 또는 운영 가능으로 표시하지 않으며 실제 구현과 검증이 필요하다.

## 3. 모든 변경의 공통 완료 조건

- [ ] 적용되는 `AGENTS.md`와 Change Envelope를 지켰다.
- [ ] 요구사항, API, DB, ADR, 운영 문서의 관련 계약이 일치한다.
- [ ] 실제 수정 경로가 Allowed·Conditional Paths 안에 있다.
- [ ] 기존 사용자 변경을 되돌리거나 덮어쓰지 않았다.
- [ ] Controller·Service·Repository·Entity·DTO 책임을 분리했다.
- [ ] 다른 도메인의 Repository와 외부 HTTP 구현을 직접 참조하지 않는다.
- [ ] 성공과 최소 한 개의 실패 또는 경계 시나리오를 자동 테스트했다.
- [ ] API는 인증, validation, 주요 상태 코드와 오류 응답이 명세와 일치한다.
- [ ] 관련 테스트와 `./gradlew test`가 통과한다.
- [ ] 실행하지 못한 검증은 이유와 범위를 기록했다.
- [ ] 비밀값, 개인정보, 사용자 원문과 외부 원문이 코드·Git·로그·fixture·오류 응답에 없다.
- [ ] 기능 완료 범위와 남은 제한을 `docs/07-implementation-readiness.md`에 반영했다.

## 4. 인증과 사용자

- [ ] 이메일 중복과 입력 형식을 검증한다.
- [ ] 비밀번호는 검증된 해시로만 저장하고 원문을 응답·로그에 남기지 않는다.
- [ ] 로그인 성공·실패와 만료·변조 JWT를 테스트했다.
- [ ] 공개 API를 제외한 지역·AI·장소·일정 API에 인증을 적용했다.
- [ ] 일정 목록·상세·수정·삭제에서 소유권을 검증한다.
- [ ] 다른 사용자의 일정과 비공개 필드를 노출하지 않는다.
- [ ] JWT secret, 만료와 키 교체 방식이 운영 설정으로 분리됐다.
- [ ] 소셜 로그인처럼 MVP 밖의 인증 방식을 추가하지 않았다.

## 5. 지역 기준 데이터

- [ ] 서울특별시·광역시·도 상위 항목과 최종 선택 가능한 시·군·구를 포함한 `regions.json`이 있다.
- [ ] 읍·면·동과 해외 지역을 포함하지 않는다.
- [ ] 대표 좌표의 공공 데이터 출처와 갱신 기준을 기록했다.
- [ ] 시작 시 ID 중복, 필수값, 상위 관계와 좌표 범위를 검증한다.
- [ ] 검색 결과와 정렬이 결정적이다.
- [ ] AI가 선택할 수 있는 지역을 같은 허용 목록으로 제한한다.
- [ ] 완료 일정에 `regionId`와 당시 표시 이름 snapshot을 저장한다.

## 6. AI

### 지역 추천

- [ ] 정확히 3개의 중복 없는 허용 지역 ID와 이유만 반환한다.
- [ ] 목록 밖 ID, 잘못된 개수와 구조 오류를 `AI_RESPONSE_INVALID`로 변환한다.
- [ ] AI가 존재하지 않는 지역을 생성해도 서버 검증에서 거절한다.

### 메뉴 분석

- [ ] 사용자 자연어를 메뉴 이름과 카카오 검색어로만 구조화한다.
- [ ] AI가 사용자의 선택이나 추천 점수를 확정하지 않는다.
- [ ] 구조 오류 재시도는 최대 한 번이며 한도에 포함한다.

### 공통

- [ ] `AiClient`, 실제 HTTP Client와 Fake Client가 분리돼 있다.
- [ ] 인증·요청 오류는 재시도하지 않고 provider 장애를 계약된 오류로 변환한다.
- [ ] 지역 AI 2회/분·10회/일, 메뉴 AI 3회/분·15회/일을 적용했다.
- [ ] 실제 OpenAI 호출 없이 자동 테스트가 통과한다.
- [ ] API 키, 사용자 원문과 OpenAI 원문을 저장·기록하지 않는다.

## 7. 카카오 장소 검색과 선택

이 절은 확정된 카카오 데이터 수명 계약을 구현하고 검증한 뒤에만 완료 처리한다.

- [ ] `KakaoPlaceClient`, 실제 HTTP Client와 Fake Client가 분리돼 있다.
- [ ] 관광지는 대표 좌표 20km 또는 주소 행정구역 일치 조건을 적용한다.
- [ ] 장소 검색 20회/분·300회/일 한도를 적용한다.
- [ ] 결과 부족 시 임의 장소를 만들지 않는다.
- [ ] 카카오 카테고리는 기본 체류 시간 계산에만 사용한다.
- [ ] 장소 유형과 카테고리를 UI·API·DB에 노출하지 않는다.
- [ ] 일반·자연 90, 박물관 120, 체험 180, 등산 240, 테마파크 360, 식사 60분의 기본값을 검증했다.
- [ ] 호텔에 관광 체류 시간을 적용하지 않는다.
- [ ] 사용자 표시 이름은 빈 입력에서 시작하고 카카오 장소명을 기본값·placeholder로 복사하지 않는다.
- [ ] 표시 이름은 trim 후 1~50자, 체류 시간은 30~480분의 10분 배수다.
- [ ] `selectionToken` 만료, 서명 변조, 역할·payload 불일치를 검증한다.
- [ ] 카카오 좌표·주소·전화번호·카테고리·장소명·원문 응답을 영속 저장하거나 캐시하지 않는다.
- [ ] 카카오 장소 ID·URL과 사용자 작성 정보만 완료 일정 저장 계약에 전달한다.
- [ ] 숙소는 기하 중앙값 5km·10km, 메도이드와 현재 지도 영역에서 탐색할 수 있다.
- [ ] 숙소에 거리 점수나 자동 추천 순위를 부여하지 않고 지도와 목록에서 사용자가 선택한다.
- [ ] 공식 정책, attribution, 쿼터와 키 제한을 구현 시점에 다시 확인했다.

## 8. 거리와 경로

### 순수 알고리즘

- [ ] Haversine의 단위, 0 거리, 대칭성과 좌표 범위를 테스트했다.
- [ ] Nearest Neighbor가 모든 장소를 정확히 한 번 방문하고 동률에서 결정적으로 동작한다.
- [ ] 2-opt 결과가 입력 경로보다 길어지지 않고 장소 집합을 보존한다.
- [ ] 반복 상한과 개선 없음 조건에서 종료한다.
- [ ] `route/algorithm`은 Spring, JPA, HTTP와 AI에 의존하지 않는다.

### 외부 경로 검증

- [ ] 일정 전체에서 `CAR` 또는 `PUBLIC_TRANSIT` 하나만 사용한다.
- [ ] 최종 후보의 인접 구간만 실제 경로로 조회한다.
- [ ] 자동차는 카카오모빌리티 Client, 대중교통은 카카오맵 Client로 분리한다.
- [ ] 경로 API가 반환한 예상 시간은 `ceil(seconds / 600) * 10`분으로 올린다.
- [ ] 별도의 고정 이동 여유를 더하지 않는다.
- [ ] 정상 경로 없음은 재시도·fallback 없이 422로 처리한다.
- [ ] 기술적 장애는 한 번 재시도하고 재실패 때만 Haversine 추정값과 warning을 사용할 수 있다.
- [ ] 자동차·대중교통 각각 60회/분·120회/일 한도를 적용했다.
- [ ] 대중교통 일일 900건 서비스 차단을 운영 문서와 테스트에 반영했다.
- [ ] 필요한 경로 쿼터를 호출 전에 원자적으로 확보하며, 부족하면 외부 호출 없이 전체 구간을 Haversine 예상시간으로 계산하고 warning을 반환한다.
- [ ] MOVE에는 10분 단위 예상 이동시간 숫자만 저장하고 출처 enum·상태와 생성 warning은 저장하지 않는다.
- [ ] 완료·공유 조회는 모든 MOVE를 예상 이동시간으로 표시한다.
- [ ] 실제 외부 경로 API 없이 Fake 기반 자동 테스트가 통과한다.

## 9. 일정 추정

- [ ] `POST /api/travel-plans/estimate`는 DB와 실제 Route Client를 호출하지 않는다.
- [ ] 여행 기간 1~7일과 각 날짜의 시작·종료 시각을 검증한다.
- [ ] 하루 관광지는 최대 5개다.
- [ ] 1박 이상은 호텔 필수이고 당일치기는 호텔을 요구하지 않는다.
- [ ] 장소 표시 이름과 체류 시간 규칙을 검증한다.
- [ ] 하루 활동 범위와 식사 허용 시간대가 60분 이상 겹치면 해당 식사 슬롯 60분을 자동 배치한다.
- [ ] 점심·저녁 허용 시간대와 12:00·18:00 우선 시각, 한쪽 기본 15분의 이동 여유와 긴 체류 중복 방지를 검증했다.
- [ ] Haversine, Nearest Neighbor와 2-opt로 추정 일정을 만든다.
- [ ] 응답이 `routeVerified=false`임을 명시한다.
- [ ] 작성 초안을 DB, 서버 세션과 중복 요청 저장소에 저장하지 않는다.
- [ ] 동일 입력에 결정적인 결과를 반환한다.
- [ ] 모든 day·order가 null이면 자동 배치하고 모두 지정되면 사용자 날짜·순서를 보존한다.

## 10. 완료 일정 생성과 DB

확정된 카카오 데이터 수명 계약을 구현하고 검증한 뒤에만 좌표 기반 생성 흐름을 완료 처리한다.

- [ ] 클라이언트의 추정 시간은 신뢰하지 않고 서버가 재계산하되 사용자 확정 날짜·순서는 보존한다.
- [ ] 경로 API가 반환한 예상 이동시간으로 날짜별 종료 시각을 다시 검증한다.
- [ ] 시간 초과 시 장소를 자동 삭제하거나 체류 시간을 줄이지 않고 저장을 거절한다.
- [ ] 외부 통신과 계산은 DB 트랜잭션 전에 끝난다.
- [ ] 모든 검증 뒤 짧은 트랜잭션으로 Aggregate 전체를 저장한다.
- [ ] 저장 실패 시 TravelPlan, Day, Item과 PlanPlace가 모두 rollback된다.
- [ ] User 소유권 FK와 의도한 UNIQUE·CHECK·FK를 migration에 반영하고 실제 DB로 테스트했다.
- [ ] 이동·체류 시간과 항목별 nullable 조합이 DB 계약에 맞는다.
- [ ] 카카오 장소 ID·URL, 사용자 작성 이름·메모·체류 시간만 PlanPlace에 저장한다.
- [ ] 좌표·주소·전화번호·카테고리·카카오 장소명·경로 원문·AI 원문을 저장하지 않는다.
- [ ] `requestId`와 상태만 10분간 보관하며 payload·response를 보관하지 않는다.
- [ ] 사용자별·서비스 전체 카운터와 requestId 상태를 MySQL 공유 테이블에 저장하고 다중 인스턴스 동시성 테스트를 통과했다.
- [ ] 필요한 호출량을 조건부 갱신으로 원자적으로 확보한 뒤 DB 트랜잭션을 종료하고 외부 API를 호출한다.
- [ ] 만료 판정과 묶음 삭제를 검증하고 운영 테이블에 외부 데이터·좌표·payload·response가 없음을 확인했다.
- [ ] versioned migration을 새로 추가하고 이미 적용된 migration을 수정하지 않았다.
- [ ] 빈 DB와 기존 검증 DB에서 migration을 확인했다.

## 11. 완료 일정 조회·편집·공유

- [ ] 목록과 상세는 인증 사용자의 일정만 반환한다.
- [ ] 완료·공유 조회는 Kakao·OpenAI·Route Client를 호출하지 않는다.
- [ ] 응답에 좌표, 주소, 카테고리와 경로선을 포함하지 않는다.
- [ ] 저장된 제목·시간표·사용자 표시 이름·메모·카카오 링크만으로 화면을 구성한다.
- [ ] 제목, 사용자 장소 표시 이름과 메모만 수정할 수 있다.
- [ ] 날짜·순서·시각·체류 시간·이동수단·장소 ID·URL 수정은 거절한다.
- [ ] 텍스트 수정으로 외부 호출이나 재계산이 발생하지 않는다.
- [ ] 장소나 동선을 바꾸려면 새 일정 생성 흐름을 사용한다.
- [ ] 삭제 시 소유권을 검사하고 Aggregate 전체를 제거한다.
- [ ] 공유 토큰의 생성·만료·변조와 읽기 전용 권한을 검증했다.

## 12. 추천

- [ ] 숙소는 제작 중 지도와 목록에서 사용자가 직접 선택하며 추천 점수를 계산하지 않는다.
- [ ] 음식점 추천 점수는 식사 시각 전후 위치에서의 이탈 비용을 사용한다.
- [ ] 음식점 후보를 목록과 지도에 함께 표시하고 마커 연동·현재 지도 재검색·사용자 직접 선택을 지원한다.
- [ ] AI 메뉴 1~5개와 검색어·이유·대상 관광지는 사용자 확정 후에만 사용하며 AI가 식당과 순위를 결정하지 않는다.
- [ ] 동률 정렬이 결정적이다.
- [ ] 후보 없음과 제공자 장애를 구분한다.
- [ ] 추천 결과가 사용자 선택이나 완료 일정을 자동으로 변경하지 않는다.
- [ ] AI가 최종 순위나 점수를 결정하지 않는다.

## 13. 운영과 보안

- [ ] 비밀값은 환경 변수 또는 secret manager로만 주입한다.
- [ ] 서버 키와 공개 가능 키를 분리하고 API·origin·도메인 제한을 적용한다.
- [ ] timeout, 재시도, 오류 변환과 fallback을 문서화하고 테스트했다.
- [ ] 사용자별 한도와 각 지도 API 공식 무료 한도의 90% 차단을 적용했다.
- [ ] 일일 한도는 `Asia/Seoul` 자정에 초기화한다.

- [ ] 지역 직접 검색과 AI 지역 추천이 국내 허용 목록으로 동작한다.

- [ ] 완료 후 허용된 텍스트만 편집할 수 있다.
- [ ] 공유 화면은 인증 없이 읽기만 가능하고 비공개 필드를 노출하지 않는다.
- [ ] 새로고침·완료·취소·탭 종료 후 좌표가 브라우저 저장소에 남지 않는다.
- [ ] 모바일·데스크톱과 키보드 핵심 흐름을 확인했다.
- [ ] 관련 브라우저 자동 테스트와 필요한 수동 smoke 결과를 기록했다.
- [ ] MVP 제외 기능을 UI에 노출하지 않는다.

# 프로젝트 요구사항 명세서

## 1. 프로젝트 개요

### 프로젝트명

**Travel - AI 여행 일정 관리 & 최적화 서비스**

### 목적

사용자가 여행 지역, 여행 취향, 반드시 방문하고 싶은 장소, 먹고 싶은 음식 등의 조건을 입력하면 해당 조건에 적합한 여행지를 추천하고, 선택된 장소들의 위치를 기반으로 이동 동선을 최적화하여 여행 일정을 생성한다.

또한 선택된 관광지들을 방문하기 유리한 위치의 호텔과 각 날짜의 여행 동선 근처에서 사용자가 원하는 음식을 먹을 수 있는 음식점을 추천한다.

---

## 2. 프로젝트 핵심 원칙

이 프로젝트에서 AI와 Spring Backend의 책임을 명확히 분리한다.

### AI가 담당하는 영역

- 사용자의 자연어 여행 요청 분석
- 여행 스타일 및 선호 조건 구조화
- 여행지 후보 생성 및 추천 보조
- 음식 관련 자연어 해석
- 사용자에게 보여줄 추천 이유나 일정 설명 생성

### Spring Backend가 담당하는 영역

- 사용자 및 여행 데이터 저장
- 장소 데이터 관리
- 여행 계획 생성 및 저장
- 장소 간 거리 계산
- 호텔 후보 평가
- 음식점 후보 평가
- 여행 경로 최적화
- 비즈니스 규칙 적용
- Validation / Exception Handling
- 인증 / 인가
- 테스트

### 금지 원칙

다음 기능을 LLM의 답변만으로 결정하지 않는다.

- 최단 이동 거리 계산
- 경로 최적화
- 호텔의 이동 효율 점수 계산
- 음식점의 동선 이탈 거리 계산

## 3. 사용자 시나리오

### 시나리오 A - 선호 조건 기반 여행지 추천

사용자가 다음과 같이 입력한다.

> 서울에서 사람이 너무 많은 곳은 피하고 싶고, 역사적인 장소와 사진 찍기 좋은 곳을 좋아해.

서비스는 자연어를 분석하여 구조화된 선호 조건을 만든다.

예:

```json
{
  "region": "서울",
  "interests": ["HISTORY", "PHOTOGRAPHY"],
  "crowdPreference": "LOW"
}
```

이 조건을 기반으로 여행지 후보를 추천한다.

---

### 시나리오 B - 방문 장소와 음식 기반 추천

사용자가 다음 정보를 입력한다.

- 지역: 부산
- 반드시 방문할 장소: 해운대, 감천문화마을
- 먹고 싶은 음식: 돼지국밥, 회

서비스는 필수 장소를 포함하면서 추가 여행지 후보와 음식점 후보를 추천한다.

---

### 시나리오 C - 여행 계획 생성

사용자가 추천 여행지 중 방문할 장소를 선택하면 시스템은 다음 과정을 수행한다.

1. 선택 장소의 위치 정보 확보
2. 장소 간 거리 계산
3. 호텔 후보 평가
4. 날짜별 방문 장소 분배
5. 날짜별 이동 경로 최적화
6. 동선 근처 음식점 추천
7. 최종 여행 일정 생성
8. 여행 계획 DB 저장

---

## 4. 기능 요구사항

### FR-01 여행 조건 입력

사용자는 다음 정보를 입력할 수 있다.

- 여행 지역
- 여행 시작일
- 여행 종료일
- 여행 선호 조건
- 혼잡도 선호
- 반드시 방문하고 싶은 장소
- 먹고 싶은 음식

---

### FR-02 자연어 여행 선호 분석

사용자가 자연어로 작성한 선호 조건을 OpenAI API를 이용하여 구조화한다.

예상 결과:

```json
{
  "interests": ["NATURE", "PHOTOGRAPHY"],
  "crowdPreference": "LOW"
}
```

AI 응답은 가능한 한 자유 텍스트가 아니라 구조화된 형태로 변환한다.

---

### FR-03 사용자 선호 기반 여행지 추천

구조화된 사용자 선호를 이용해 여행지 후보를 추천한다.

추천 시 고려할 수 있는 조건:

- 지역
- 여행 스타일
- 장소 카테고리
- 혼잡도 선호
- 사용자가 이미 지정한 필수 여행지

초기 MVP에서는 추천 규칙을 단순하게 유지한다.

---

### FR-04 필수 여행지 지정

사용자는 반드시 방문할 장소를 입력하거나 선택할 수 있다.

필수 장소는 일정 생성 과정에서 임의로 제거하지 않는다.

---

### FR-05 음식 선호 입력

사용자는 여행 중 먹고 싶은 음식을 복수로 입력할 수 있다.

예:

- 돼지국밥
- 회
- 밀면

---

### FR-06 여행 계획 생성

서비스는 다음 데이터를 이용해 여행 계획을 생성한다.

- 여행 기간
- 필수 여행지
- 선택된 추천 여행지
- 위치 정보
- 호텔
- 음식점
- 장소별 예상 체류 시간
- 향후 운영 시간 정보

---

### FR-07 장소 간 거리 계산

각 장소의 위도 / 경도를 이용하여 장소 사이의 거리를 계산할 수 있어야 한다.

초기 구현은 직선 거리 계산으로 시작할 수 있다.

향후 지도 API를 도입하면 실제 도로 이동 거리 또는 이동 시간으로 교체할 수 있다.

---

### FR-08 여행 경로 최적화

선택된 여행지의 방문 순서를 결정한다.

#### 초기 알고리즘

Nearest Neighbor

현재 위치에서 가장 가까운 미방문 장소를 반복해서 선택한다.

#### 개선 알고리즘

2-opt

Nearest Neighbor가 만든 초기 경로의 일부 간선을 교환하여 전체 이동 거리를 개선한다.

---

### FR-09 호텔 추천

여행지 후보와 각 호텔 후보 사이의 이동 비용을 계산하여 이동 효율이 높은 숙소를 추천한다.

초기 점수:

```text
HotelScore =
Σ distance(hotel, selectedPlace)
```

점수가 낮을수록 이동 측면에서 유리한 호텔이다.

향후 고려 가능 요소:

- 가격
- 평점
- 역 / 공항 접근성
- 체크인 / 체크아웃
- 사용자의 숙박 선호

---

### FR-10 음식점 추천

사용자가 먹고 싶은 음식과 여행 동선을 함께 고려하여 음식점을 추천한다.

초기 기준:

- 음식 종류 일치 여부
- 여행 경로로부터의 이탈 거리

향후 기준:

- 평점
- 리뷰 수
- 영업시간
- 가격대

---

### FR-11 날짜별 일정 생성

여행 기간과 선택 장소 수를 고려하여 장소를 날짜별로 배치한다.

초기 버전은 장소 수를 비교적 균등하게 나누고 날짜별 경로를 최적화한다.

향후에는 다음을 고려한다.

- 영업시간
- 체류시간
- 식사시간
- 장소 중요도
- 휴식 시간

---

### FR-12 여행 계획 CRUD

사용자는 생성된 여행 계획을 조회, 수정, 삭제할 수 있어야 한다.

---

### FR-13 회원 기능

MVP 핵심 기능 완성 후 추가한다.

- 회원가입
- 로그인
- 자신의 여행 계획 조회
- 자신의 여행 계획 수정 / 삭제

인증은 Spring Security + JWT 도입을 검토한다.

- OpenAI API 연결
- 자연어 여행 조건 구조화
- 여행지 후보 추천

### MVP-4: 최적화 기능

- 위도 / 경도 거리 계산
- Nearest Neighbor 경로 생성
- 호텔 이동 거리 점수 계산
- 동선 기반 음식점 추천
- 날짜별 일정 생성

### MVP 완료 기준

아래 입력을 하나의 여행 계획으로 처리할 수 있다.

```text
지역: 부산
기간: 2박 3일

선호:
- 바다
- 사진
- 사람이 지나치게 많은 장소는 선호하지 않음

필수 장소:
- 해운대
- 감천문화마을

음식:
- 돼지국밥
- 회
```

서비스는 다음 결과를 반환할 수 있어야 한다.

- 추천 여행지 목록
- 추천 호텔
- 추천 음식점
- Day 1 / Day 2 / Day 3 일정
- 최적화된 방문 순서
- 최종 여행 계획 ID

## 6. 비기능 요구사항

### NFR-01 보안

- OpenAI API Key를 소스 코드에 작성하지 않는다.
- `.env` 또는 환경변수를 이용한다.
- `.env`는 Git에 커밋하지 않는다.
- 비밀번호를 저장하게 될 경우 평문으로 저장하지 않는다.

### NFR-02 유지보수성

- Controller는 HTTP 요청 / 응답 처리에 집중한다.
- Service는 비즈니스 로직을 담당한다.
- Repository는 데이터 접근을 담당한다.
- Entity와 API DTO를 구분한다.
- 도메인별 패키지 구조를 사용한다.

### NFR-03 테스트

최소한 다음에는 자동 테스트를 작성한다.

- 거리 계산
- Nearest Neighbor
- 2-opt 도입 시 경로 개선
- 호텔 추천 점수
- 음식점 추천 점수
- 핵심 Service 비즈니스 로직

### NFR-04 관찰 가능성

개발 단계에서는 SQL 로그와 애플리케이션 로그를 이용해 요청 및 DB 동작을 확인한다.

향후 운영 배포 시 민감 정보가 로그에 출력되지 않도록 조정한다.

# User Domain Instructions

## Responsibility

회원, 인증 사용자 식별, JWT 인증에 필요한 사용자 계약과 사용자별 호출 한도 기반을 관리한다.

## Rules

- 인증은 장소·일정·외부 호출의 선행 기능이다.
- 비밀번호는 검증된 해시만 저장하고 원문을 로그·응답에 남기지 않는다.
- Spring Security·JWT 설정은 `global/security`, 사용자 데이터와 정책은 `user`에 둔다.
- 인증 사용자 ID는 Controller 입력의 userId가 아니라 검증된 인증 정보에서 얻는다.
- 사용자별 분·일 한도, API별 서비스 전체 일 한도와 `requestId` 상태는 MySQL 공유 저장소를 사용하며 결과 리소스 ID·payload·response·사용자 원문을 저장하지 않는다.
- 기능별 사용자·서비스 한도와 제공자 차단선은 API·운영 계약을 단일 기준으로 사용하며 `Asia/Seoul` 자정에 일일 창을 바꾼다.
- 대중교통을 포함한 제공자별 신규 호출 차단선을 적용하고 공식 한도와 운영 설정은 구현 직전 다시 확인한다.
- 조건부 갱신과 짧은 트랜잭션으로 필요한 호출량을 원자적으로 확보한 뒤 외부 호출 전에 트랜잭션을 끝낸다.
- `requestId` 처리 상태는 10분 수명으로 관리하고 만료 행을 정리하되 서버 재시작으로 유효 기록을 잃지 않는다.
- 같은 requestId가 처리 중이면 `REQUEST_IN_PROGRESS`, 이미 성공했으면 `REQUEST_ALREADY_COMPLETED` 상태를 공개 계약으로 전달하고 외부 호출·저장·호출량 차감을 반복하지 않는다. 만료 뒤에는 새 요청으로 처리할 수 있다.
- 일정 소유권 연결은 travelplan의 공개 계약과 협력하고 일정 계산을 중복 구현하지 않는다.
- 소셜 로그인과 승인되지 않은 권한 기능을 추가하지 않는다.
- API·DB·운영·테스트 계약을 각각 관련 문서에서 확인한다.

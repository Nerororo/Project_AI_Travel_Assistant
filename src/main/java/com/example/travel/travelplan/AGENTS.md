# Travel Plan Domain Instructions

## Responsibility

작성 중 일정 계산을 조정하고 완료된 TravelPlan Aggregate의 생성·조회·제한 편집·삭제·공유를 관리한다.

## Rules

- 지역은 region, 장소는 place, 경로는 route, 추천은 recommendation의 공개 Service·DTO를 사용한다.
- AI Client와 다른 도메인의 Repository·내부 구현을 직접 참조하지 않는다.
- estimate는 Haversine 기반이며 DB와 실제 Route Client를 호출하지 않는다.
- estimate는 모든 장소의 날짜·순서가 비어 있으면 자동 배치하고 모두 지정되면 사용자 배치를 보존한다.
- 완료 생성은 사용자 확정 날짜·순서를 검증·보존하고 이동시간을 재계산해 최종 인접 구간만 실제 경로로 확인한다.
- 여행 기간은 최소 1일·최대 7일이고 하루 관광지는 최대 5개다. 경로 쿼터를 확보하지 못하면 외부 호출 없이 전체 구간의 Haversine 예상시간과 warning을 사용한다.
- 점심은 11:30~14:00에서 12:00을, 저녁은 17:30~20:30에서 18:00을 우선해 60분으로 배치한다. 일반 식사에는 한쪽 기본 15분의 이동 여유를 확보하고 긴 체류 안의 식사·왕복 이동은 체류시간에 중복 합산하지 않는다.
- 저장 전에 선택한 음식점만 MEAL에 연결하며 선택하지 않은 MEAL은 장소 없이 저장한다.
- 경로 API가 반환한 예상 이동시간으로 종료 시각을 넘으면 저장하지 않고 장소 삭제·체류 축소를 자동 수행하지 않는다.
- 외부 호출과 계산을 마친 뒤 짧은 트랜잭션으로 Aggregate 전체를 저장한다.
- 작성 초안을 DB·서버 session에 저장하지 않는다.
- PlanPlace에는 카카오 ID·URL과 사용자 작성 이름·메모·체류 시간 등 허용 필드만 저장한다.
- MOVE에는 출처 enum이나 생성 warning 없이 10분 단위 `estimatedMinutes` 숫자만 저장한다.
- 완료 후 제목·사용자 장소 이름·메모만 수정하며 재계산·외부 호출을 하지 않는다.
- 완료·공유 조회는 저장 데이터만 사용하고 좌표·지도·경로선을 반환하지 않는다.
- 모든 일정 API에 인증·소유권을 적용하고 Entity를 직접 반환하지 않는다.

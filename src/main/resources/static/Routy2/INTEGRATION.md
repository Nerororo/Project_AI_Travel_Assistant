# Routy2 디자인 미리보기와 S1 연결 안내

## 실행

`index.html`을 브라우저에서 직접 열 수 있다. 모든 시각 자산은 자체 HTML/CSS/SVG이며 외부 폰트·CDN·이미지·API에 의존하지 않는다.

HTTP 미리보기가 필요하면 프로젝트 루트에서 다음을 실행한다.

```powershell
node src/main/resources/static/Routy2/preview-server.cjs
```

주소는 `http://127.0.0.1:4173`이며 이 서버는 Routy2 화면 자산만 읽는다. Spring 실행 시 주소는 `/Routy2/index.html`이다.

## 현재 범위

- 사용자가 요청한 독립 시안이며 S1 완료 또는 실제 사이트 완료가 아니다.
- `static/image.png`의 코발트 블루, 흰 검색 패널, 좌측 탐색, 카드 계층을 참고했다. 서비스명·로고·문구·시각 자산은 새로 작성했다.
- 입체 엽서, 포인터 기울기, 부유 모션, 배경 깊이를 CSS로 구현했다. OS의 동작 줄이기와 화면의 모션 끄기를 지원한다.
- 9단계의 UI 입력과 분기, 상태 표시를 제공한다. 표시 데이터는 예시이며 실제 장소 검증·추천·일정 계산·계정·저장은 수행하지 않는다.
- 입력은 현재 탭의 메모리에만 유지한다. 새로고침하면 초기화된다. 사용자 원문이나 토큰을 브라우저 저장소·로그에 남기지 않는다.
- 일정 결과는 부산 2026-10-01~03의 고정 예시다. 날짜·도시·체류 등의 입력 변경에 따라 시간표를 계산하지 않는다. 날짜 배정 입력도 시간표를 변경하지 않는다.
- 로그인 입력은 비활성화하고 완료 상태만 체험한다. 실제 회원정보를 수집하지 않는다.
- 지도는 CSS 개념 배치다. 실제 좌표·도로·Google 지도로 가장하지 않는다.
- 첫 시안의 화면 구성을 유지하며 국가 선택을 기본으로 표시한다. 국가 → 도시 선택 → 여행 조건 순서로 진행한다. 기존 도시 직접 선택 탭은 별도 진입 경로로 유지한다.
- 직접 입력 검색창은 국가 선택 다음의 도시 추천 카드 바로 아래에만 제공한다. 한글 부분 검색과 영문 검색(Busan/Seoul/Jeju)이 가능하다. 검색 결과를 클릭하거나 Tab·Enter로 고르면 같은 화면에서 선택 도시만 갱신한다. ‘다음 단계’를 눌러 여행 조건으로 이동하며 검색어는 탭의 메모리에 유지한다.
- 국가가 대한민국뿐인 것은 예시 데이터 범위를 제한했기 때문이다. DB 구축 여부와 무관하며 실제 국가·도시 검색은 Google Places를 연결한다. 검색 결과가 없다는 미리보기 안내는 실제 장소가 없다는 뜻이 아니다.

## 요구사항별 화면과 연결 위치

| 문서 흐름 | 현재 화면 | 실제 연결 및 남은 검증 |
|---|---|---|
| 1. 국가·도시 선택 | 메인 검색과 `render()` step 0 | 제한된 브라우저 키로 Google 자동완성. 도시 선택은 POST `/api/destinations/cities/resolve`. 검증된 Place ID만 상태로 유지 |
| 2. 국가의 AI 도시 후보 | step 1, 도시 직접 선택 시 생략 | POST `/api/destinations/cities/recommend`. 국가별 3~5개 검증 후보와 이유를 렌더링 |
| 3. 여행 조건 | step 2, 날짜·하루 시각·여유·음식 입력 | 서버 validation과 `fieldErrors`를 각 필드에 연결. 1~14일, 여유 0~60, 음식 1~5개의 UI 사전 검증 제공 |
| 4. 필수·추천 관광지 | step 3, 필수 체크·체류 시간·검색 | Google 자동완성과 POST `/api/recommendations/places`; 20개 결과까지 대응, 선택 변경 시 호텔 후보 무효화 |
| 5. 호텔 선택 | step 4, 선택된 관광지 요약·호텔 카드 | POST `/api/recommendations/hotels`; `name`, `totalDistanceKm`, `rank` 표시. 직접 호텔 검색도 실제 연결 시 지원 |
| 6. 생성·시간표·지도 | step 5, 날짜 탭·마커·식사 슬롯 | POST `/api/travel-plans`의 201 응답을 저장 상태로 전환. `renderPlan()`을 실제 `days`, `places`, `mealSlots`, `hotel`, `assumptions` 렌더러로 교체 |
| 7. 날짜 배정 수정 | step 6, 전체 장소의 날짜 입력·실패 예시 | PUT `/api/travel-plans/{id}`에 전체 입력과 `dayAssignments` 전송. 응답 성공 후에만 일정 전체 교체. 생략값 규칙 준수 |
| 8. 식사 슬롯 검색 | step 7, 날짜·식사·음식·두 빈 결과 | POST `/api/recommendations/restaurants`에 ID·날짜·mealType·food·size만 전송. 도시·시간표·여유를 보내지 않음. 실제 응답 슬롯 시각을 표시 |
| 9. 로그인·내 여행 | step 8, 가입·로그인·목록·재조회·삭제·소유권 오류 예시 | U1 계약 확정 후 POST `/api/users`, POST `/api/auth/login`, GET `/api/users/me/travel-plans`, 상세 GET 및 DELETE 연결 |

도시 직접 검색의 연결 지점은 `citySearch()`, `renderCityResults()`, `data-search-city` 선택 처리다. S1에서는 Google 자동완성 결과의 Place ID를 받아 도시 resolve API 검증 성공 후 선택을 확정한다. 국가 경로에서는 선택 국가와 일치하는 도시를 검색·검증하며, ‘다음 단계’로 여행 조건에 진입한다. 검색으로 국가 경로를 직접 도시 경로로 바꾸지 않는다. 자유 입력 문자열을 확정 도시로 취급하지 않으며, 이전 검색 응답이 최신 검색 결과를 덮어쓰지 않게 요청 취소·버전 검사를 적용한다.

## 연결할 때의 코드 경계

`preview.js`의 `simulate()`는 로딩 상태를 보여주기 위한 지연일 뿐 API adapter가 아니다. 실제 연결 작업에서는 별도 API 모듈에 JSON 요청, timeout/취소, 상태 코드 변환을 구현하고 위 호출 위치에서 사용한다. 화면 렌더링 함수와 CSS·HTML 구조는 재사용할 수 있으나 예시 데이터·미리보기 컨트롤은 운영 화면에서 제거한다.

- 서버 확인 전 화면에서 저장 성공으로 바꾸지 않는다. 생성 응답 ID를 이후 요청에 사용한다.
- Google Place ID를 예시 키 `busan`이나 배열 순번으로 대체하지 않는다.
- 일정 계산·경로 최적화·추천 순위 계산은 JavaScript에 구현하지 않는다.
- GET은 표시 정보를 갱신할 뿐 일정 재계산을 하지 않는다.
- PUT에는 임시 편집 상태를 보내고 실패 시 기존 응답 상태를 보존한다.
- 음식점 검색 결과는 일정 데이터와 분리하고 두 `emptyReason`과 503을 구분한다.
- 지도 실패·좌표 오류가 시간표를 지우지 않도록 독립된 지도 오류 상태를 유지한다.
- 실제 지도는 서버 응답 좌표로 호텔·관광지 마커와 번호만 표시한다. 도로 polyline은 추가하지 않는다.
- 로그인·토큰·페이징 계약은 현재 미확정이다. U1에서 정한 정책에 맞춰 구현한다.
- 요청 중 중복 제출 방지, 이전 요청 취소 또는 응답 버전 비교를 적용한다. 현재 미리보기는 창을 닫으면 지연 응답을 무시한다.

## 디자인 확정 시 검토할 항목

- 현재 시안은 모든 단계를 모달에서 진행한다. 실제 S1-01에서 전체 페이지형 작업 화면으로 확장할지 결정한다.
- 현재 시안의 목표는 디자인 확인이다. 실제 14일·84개 장소를 처리하는 목록, 전체 날짜 배정, 이동 여유 재편집, 장소 추가·삭제, 호텔 직접 검색을 S1에서 실제 응답에 맞춰 확장해야 한다.
- 현재 Routy2는 이번 사용자 요청에 승인된 별도 경로다. 후속 작업에서 계속 사용할지는 S1-01 Change Envelope와 기존 하네스 경계에 명시해야 한다. 이 작업은 docs나 AGENTS.md를 변경하지 않았다.

## 검증

```powershell
node --check src/main/resources/static/Routy2/preview.js
node --test src/main/resources/static/Routy2/preview.test.cjs
```

실제 API·DB·인증·브라우저 E2E와 외부 provider smoke는 아직 검증되지 않았다. `docs/08-test-strategy.md`와 `docs/10-definition-of-done.md`의 S1 완료 조건은 실제 연결 후 별도로 통과해야 한다.
